# 空间办公 Spatial Office · design-doc（第 2–3 轮，2026-11-10；2b = 门 B 前补充的三条，2c = 门 B「改」）

由 PICO CLI `pico-spatial-app-designer` skill（pico-spatial-agentic-tools 0.7.0-beta.2）按 Frame → Explore → Plan → Critique 走到门 B。第 1 轮（docx / xlsx / pptx 原样编辑、只有平面窗口）被用户在门 B 打回，材料存在 `round1/`。Write Spec 和 Consistency Review 等用户过门 B 再做（Spec 记录的是已批准的 Preview）。

用户意见（原话）：「真的能编辑哪些吗？应该是需要转成一个可以编辑的我们自己的格式，比如 spatialdoc, spatialppt, spatialsheet，然后加上对应的 spatial 平台下特点，比如空间排布，curved，空间化图表」「最后也可以转成 MS 的 doc, slides, excel，和 google 的」。

## 1. Frame

```text
Frame Design Record
├─ User task: 把办公文件导入成自己的空间格式（SpatialDoc / SpatialSlides / SpatialSheet），
│             用键鼠编辑，把内容在身边铺开来看和改，最后导出回通用格式
├─ Spatial value: (1) 一份文件的多个部分同时摊在身边：文档的章、演示的页、宽表的列，
│                     不用滚动和翻页；摆法存在文件里，下次原样还原
│                 (2) 沿圆弧排开，每一块都正对人（曲面），宽表和长文两端不再斜着看
│                 (3) 表格选区变成能转着看的 3D 图表实体，跟数据联动；演示预演时出屏
├─ Content form: 2D 为主（文字、表格、幻灯片），3D 辅助（空间图表）；
│                铺开和预演时是「2D 面板在 3D 场景里的排布」
├─ Container: 三种，按任务用
│   ├─ Planar 窗口（Shared Space）：主页、文档 / 表格 / 演示三个编辑窗口
│   ├─ Volume 窗口（Shared Space）：平面编辑时打开的空间图表
│   └─ Stage（Full Space，Mixed 透视）：「铺开」和「预演」
└─ Rationale: 打字和读文件是页面式任务，用 Planar，和别的应用并排。
              空间排布要应用自己决定每一块的位置并保存还原；Shared Space 里窗口位置归系统，
              应用拿不到也设不了，所以铺开必须进 Stage。用 Mixed 是因为主输入是真实的键盘鼠标，
              人要看得见自己的桌子。3D 图表在平面编辑时需要一块有边界的 3D 区域，用 Volume。
```

前提与边界：
- 中英双语，设置里切换；设置里有「退出应用」。
- 键鼠是主输入；手柄射线、手势射线、眼手（注视 + 捏合）都能点到所有控件。
- Shared Space 里窗口位置由系统决定，不承诺「回到面前」。铺开（Stage）里的位置由应用决定，相对座位保存。
- 全部离线，不需要账号。Google 只通过「导出的办公文件可以被 Google 导入」支持；直传网盘不在 v1。
- 曲面：CLI 的 skill、组件和 SDK 参考里都没有曲面面板。方案是「分段折面」：若干平面板沿圆柱排，每块正对座位，接缝落在内容的自然边界（列线、页边、页间距）。见第 5 节和 PRD。

### 2.2 W0 主页
- SideNavigation：最近 / 新建 / 设置。三个稳定目的地，窗口里已有侧栏，不再加 TabBar。
- 最近：TitleBar（标题 + 副标题），trailing [导入文件…]（系统文件选择器）。正文两组 ListItem：
  - 「空间文件」：文件类型图块、文件名（带扩展名）、类型 · 规模 · 布局名 · 时间。点一行打开对应编辑窗口。
  - 「可导入的办公文件」：虚线灰图块（DOCX / XLSX）、文件名、位置 · 大小 · 会转成什么，尾部 Chip「导入」。点一行打开导入对话框。
- 新建：三张卡（空间文档 / 空间表格 / 空间演示），点了直接开新窗口。
- 设置：语言（SegmentControl）、导入时把原文件存进包里（Switch）、铺开时离你多远（SegmentControl 1.2 / 1.5 / 1.8 m）、键盘快捷键（打开 Sheet）、关于、[退出应用]（AlertDialog 确认）。

### 2.3 导入对话框（Sheet）
- 标题「导入「文件名」」。一句说明：转成哪种空间格式，原文件不改动。
- 三行结果，各带图标、标题（含数量）和明细：可编辑 / 近似转换 / 占位保留。
- ListItem + Switch：把原文件存进包里（多占多少、有什么用）。
- ListItem：保存到哪里。
- 底部右对齐主按钮 [转换并打开]；点了之后按钮换成进度条和步骤文字，完成后关闭对话框、打开编辑窗口，Snackbar「已转换… N 项需要留意」带 [看报告]。

### 2.4 W1 文档
- TitleBar：leading 关闭；标题 = 文件名；副标题 = 已自动保存 · 章数 · 当前布局名；trailing [导入报告 N]（只有导入来的文件有）+ 更多（另存为、取回原文件、键盘快捷键）。
- 正文：白色纸面直接编辑。块类型：标题、段落、列表、表格、图片、空间图表（联动块，平面里显示 2D）、占位块（虚线框，说明是什么、为什么不能编辑、原件在哪）。被钉成卡片的块右边有图钉标记。
- Toolbar（segmented）：主组 = 样式（Menu：正文 / 标题 1 / 标题 2，标题 2 开新的一章）、粗体、斜体、下划线、项目符号、图片、表格、[钉卡]、撤销、重做；辅组 = [铺开]、[导出]。没有保存按钮：自有格式持续自动保存，状态写在副标题里。
- Subwindow「导入报告」：来源文件、三类数量、逐条列表（类型小标签 + 标题 + 说明），点一条正文滚到对应位置并闪一下。

### 2.5 W2 表格
- TitleBar 同上（副标题 = 已自动保存 · 工作表数 · 空间图表数）。
- 公式栏：当前单元格名 + 单行输入框，Enter 提交、Esc 取消。
- 网格：示例是 14 列 × 16 行，平面窗口一屏放不下 14 列，要横向滚动；图表的数据区用浅蓝底标出。点选、方向键 / Tab / Enter 移动、双击或直接输入编辑。
- 网格下：工作表 SegmentControl + 一行说明（蓝色底是什么）。
- Toolbar：主组 = 粗体、数字格式（Menu）、Σ、排序、插入行、[3D 图表]、撤销、重做；辅组 = [铺开]、[导出]。

### 2.6 V1 空间图表（Volume）
- 3D 柱状图：X = 月份（12），Z = 系列（4），高度 = 值；四个系列固定配色（#2a78d6 / #eb6834 / #1baf7a / #eda100，已过色盲与对比校验，对比偏低的两色靠图例和点选读数补）。
- 3D 散点图：三列数值作 X / Z / Y，带落地线。
- 场景内：左上透明标签（标题、数据来源、图例）；右上带玻璃底的值卡片（当前选中项的名字和数值、一行操作提示）。
- 交互：拖动绕竖轴转；点一根柱子 / 一个点 = 表格里选中对应单元格；表格里选中数据区单元格 = 对应柱子高亮；改单元格 = 柱高变。
- Toolbar：柱状 / 散点（SegmentControl）、复位视角、[放进演示]；辅组 = 关闭。

### 2.7 W3 演示
- 左：按章分组的缩略图；右：16:9 画布直接改字，下面讲者备注。
- 页上可以放「3D 对象」（空间图表或 3D 模型）：平面里是 2D 预览 + 标记「3D · 预演时出屏」。
- Toolbar：主组 = 新建页、版式（Menu：标题页 / 标题 + 正文 / 正文 + 3D 对象）、文本框、形状、图片、[3D 对象]、撤销、重做；辅组 = [故事线]（= 铺开）、[导出]。TitleBar trailing [预演]。

### 2.8 S1 铺开（Stage，座位坐标系）

坐标：原点 = 进入时头的位置（只取水平朝向），+X 右、+Y 上、−Z 前，单位米和度。每块存方位角 azimuth（正前 0，右为正）、半径 radius、高度 elevation（相对眼高）、宽度、层 layer。不依赖房间识别。

三种排布（布局条上切换，Ctrl+Alt+1/2/3）：

| | 文档（每章一页 0.6 × 0.8 m） | 表格（每 3 列一段，高 0.78 m） | 演示（每页 0.56 × 0.315 m） |
|---|---|---|---|
| 并排 | 5 页排成直线，间距 0.64 m，距离 1.5 m | 5 段共面，一整块 2.9 m 宽的平表，距离 1.4 m | 8 页排成直线，间距 0.6 m，距离 1.8 m |
| 环绕（曲面） | 半径 1.5 m，每页隔 25°，都正对座位 | 半径 1.4 m，相邻段边对边，每段约 16–28° | 半径 1.8 m，每页隔 18.5°，章之间多 6° 缺口，章名在上方 |
| 分层 | 焦点页和左右各一页在 1.3 m；其余退到 2.3 m、抬高 0.78 m、放大 1.45 倍、变淡 | 「销售」表在 1.4 m 弯着；「门店」表退到 2.4 m、抬高 0.86 m、放大 1.5 倍 | 当前章在 1.5 m；其余章退到 2.6 m、抬高 0.62 m、放大 1.35 倍 |

- 焦点：同一时刻只有一块有键盘焦点（蓝框）。点另一块，或 ◀ ▶（Ctrl+Alt+← / →），整圈转动，把那一块转到正前方（方位角 0）。人不用扭着头打字。
- 钉卡：从正文拎出来的块（示例是表格），固定在右前上方（方位角 50°、半径 1.35 m、高 +0.62 m），转圈时不动。
- 桌面 3D 图表：右前方桌面高度（0.64, −0.48, −0.56 m），尺寸约 0.5 × 0.23 × 0.22 m，不挡面板。
- 布局条：场景内带玻璃底的操作条，在焦点块正下方约 0.35 m，朝向人，不随圈转。内容：并排 / 环绕 / 分层（SegmentControl 带图标）、◀、▶、布局名（Menu：写作 / 评审 / 把现在的摆法存成新布局…）、[收起]。
- 进入时 Snackbar 说明「已进入全空间，别的应用窗口暂时隐藏，点 [收起] 回来」。[收起] 关 Stage，回到进入前的编辑窗口。
- 每次切排布、换焦点、拖动某块都写进文件的 `spatial.json`。

### 2.9 S2 预演（Stage）
- 大屏：3.2 × 1.8 m，正前 3.4 m，中心高 +0.62 m，平的。
- 备注面板：0.5 × 0.62 m，左 58°、1 m、高 −0.3 m。计时 + 下一页面板：右 58° 对称位置。
- 当前页嵌的空间图表出屏：屏幕右下前方约 1.2 m 处的 3D 实体。
- 预演条（场景内操作条，大屏下方、桌面距离）：上一页、页码、下一页、计时、[结束预演]。键盘 → ← / 空格翻页，Esc 结束。

### 2.10 导出对话框（Sheet）
- 标题「导出「文件名」」。
- 格式单选（3 行，每行：扩展名块 + 名称 + 一句用途）：办公格式（.docx / .xlsx / .pptx，带 Chip「可导入 Google」）、PDF、Markdown 或 CSV。
- 「导出后会变成这样」：按当前文件和所选格式列出每一类内容的去向，行尾标签四选一：原样 / 转 2D / 展平 / 转图片 / 不导出。
- ListItem + Switch：图表旁边再放一张 3D 视角截图（只在办公格式和 PDF 出现）。
- ListItem：保存到哪里。
- 底部：一行说明（空间文件本身不变）+ 主按钮 [导出]。完成后 Snackbar「已导出 … N 项已降级」带 [分享…]。

### 2.11 关系 / 状态保留
- 主页点空间文件 → 新编辑窗口；点办公文件 → 导入对话框 → 转换完成 → 新编辑窗口。
- 编辑窗口 [铺开] → 关闭 Shared Space 里的编辑窗口内容交给 Stage 显示；[收起] → 回编辑窗口，焦点块对应的位置滚到可见。
- 表格与图表、文档 / 演示里的联动图表共用同一份数据：改单元格，三处一起变。
- 语言切换即时作用于所有窗口和场景内面板；用户文件内容不翻译。

## 2b. 门 B 之后用户补充的三条（2026-11-10，写在 brief 里；本节覆盖 2.2、2.3、2.10 里冲突的部分）

用户原话：「然后也加个 feishu cli 登录，可以写飞书文档」「就是这个空间办公需要 seamlessly 把常用的格式文档导入，导出，MS, google, pdf, png 这些」「而且需要支持 pico browser 打开飞书，和 spatial 格式的 docs, ppt, sheet」。

Frame 的变化：用户任务从「导入成空间格式再导出」变成「常用格式点一下就打开，改完存回原格式原位置」；空间格式退到底层做工作副本，用户平时看不到。容器决定不变。

### 2b.1 打开（替换 2.3 的导入对话框）
- 主页「最近」直接列真实文件名（.docx / .xlsx / .pptx / .pdf），分「这台设备」和「云端（需要登录）」两组。没有「导入」这个动作。
- 云端一组有飞书云文档和 Google 表格各一行（尾部 Chip 标来源）。列表最后一条说明其他入口：浏览器下载的文件、系统「分享」和「打开方式」、飞书 / Google 文档链接。主页窗口高度从 720 加到 800 dp 以放下这一条。
- 点文件：直接进编辑窗口。纸面上方出现一条提示条（应用内容区，宽 720，`fillSemilight`，radius 16）：转换中显示步骤文字和 LinearProgress；完成后变成「已打开 … · 46 项可直接编辑 · 3 项近似 · 2 项占位」，带 [查看]（打开「兼容性」Subwindow）和关闭。
- 标题栏：标题 = 原文件名；副标题 =「改动已保存 · 存回 <原路径>」；trailing [兼容性 N] + 更多（另存为空间格式…、打开备份的原件、用浏览器打开网页版查看器、键盘快捷键）。

### 2b.2 存回（新增）
- 三个编辑窗口的 Toolbar 辅组变成 [铺开] [导出] [存回]，[存回] 是主色。Ctrl+S 同效。
- 文档第一次存回：Sheet（640）「存回「文件名」」，五行，行尾标签：原样 / 放回 / 可还原 / 有变化 / 丢失；一行「原件备份到」；底部 [另存为副本] + 主按钮 [备份并存回]。左上关闭 = 取消。之后的存回只出 Snackbar。
- 表格和演示示例里没有会丢的内容，直接 Snackbar「已存回 …」。

### 2b.3 导出（替换 2.10）
- Sheet 宽 720。六个目标排成 3 × 2 的选项块（扩展名小块 + 名称，单选）：PDF、图片、飞书、副本（.docx / .xlsx / .pptx，带 Chip「可导入 Google」）、空间格式、第六项（文档和演示是「网页（自带查看器）」，表格是 .csv）。
- 选项块下一行说明；「导出后会变成这样」逐条列，行尾标签：原样 / 可还原 / 转 2D / 展平 / 转图片 / 不带走。
- 选飞书且没登录：底部按钮变成「登录飞书后导出」，点了去账号页并打开登录 Sheet。

### 2b.4 账号（新增）
- 主页 SideNavigation 加第三项「账号」（最近 / 新建 / 账号 / 设置）。
- 账号页：两行 ListItem，飞书和 Google 各一行：状态说明 + trailing [登录] / [退出登录]。下面一条说明「登录后应用能做什么」。两家用同一个登录 Sheet，标题和第一步文案不同。
- 登录 Sheet（560）：一句说明；左边二维码（示意图案）、右边两步说明和一组大号短代码；等待中的进度条；样稿用 [我已同意] 模拟完成。

### 2b.5 浏览器互通（新增，示意）
- 浏览器 → 应用：系统浏览器里的云文档页面上弹出「打开方式」，第一项是空间办公（打开并编辑，改动存回这篇云文档），第二项只下载。浏览器窗口是说明用的示意，不是应用界面。
- 空间格式 → 浏览器：网页版查看器。顶上一条：文件名、[在空间办公中打开]、[空间视图（需要 WebXR）]；下面是平面版正文，只读。

### 2b.6 设置的变化
- 「导入时把原文件存进包里」换成「第一次存回前备份原件」（Switch）。
- 新增「新文件存成：通用格式 / 空间格式」（SegmentControl，默认通用格式）。

## 2c. 门 B 第 3 轮（用户「改」，2026-11-10；本节覆盖 2b.4，并补充 2b.3、2b.5）

用户原话：「把飞书CLI 授权的流程也做一下，确保能和飞书联动，办公软件里导出到飞书文档，或者用飞书 CLI 把一个文档在 PICO 这个办公软件里打开。另外也连 google drive 登录 one drive 那些。」

### 2c.1 主页导航
最近 / 浏览 / 新建 / 账号与云盘 / 设置，五项。窗口仍是 1120 × 800 dp。

### 2c.2 账号与云盘（替换 2b.4）
- 四行 ListItem：飞书、Google Drive、OneDrive、Dropbox。每行：名字、状态说明、trailing 按钮。
- 状态和按钮：未连接 → [连接]（主色）；已连接：谁 → [管理]（次要色）；登录已过期 → [重新登录]；授权被取消 → [重新连接]。
- 下面一条说明「连接后应用能做什么」。WebDAV 不出现在界面上（只能用密码连接，和规矩冲突）。

## 2d. 第 4 轮（PRD v0.6）：不自造格式

门 B 第 3 次「改」的原话：「不需要定义 spatial doc 等格式，而是用这个软件自动打开后就是呈现 spatial 那些，类似 webspatial 兼容 html 那些，我们不需要一个新的格式。」（profile B32）。本节取代前面所有关于自有格式、转换、降级、占位放回、附加数据、网页版查看器的内容。

### Frame（重做）
- 应用是标准文件的一种空间化打开方式。内容 = 文件本身（标准格式）；呈现 = 应用加的一层（摆位、曲面、3D 图表、钉卡）。
- 成功标准改成：打开不改文件；保存后解包对比只有动过的部件不同；困难组里这里看不懂的对象回到电脑上都还在、还能编辑。

### Explore（取舍）
| 问题 | 选的 | 没选的和原因 |

| 怎么保证看不懂的内容不丢 | 保存只改写动过的部件里的对应节点，其余原封不动 | 从模型重新生成整份文件（上一版的做法，需要占位放回，容易丢） |
| 布局存哪 | 默认应用数据（按路径 + 指纹 / 账号 + 文件 id），可选文件旁边的 `.spatial.json` | 写进文件的自定义部件（用户明确说不改原文件格式） |
| 打开时的空间化 | 窗口里先做能做的（图表自动 3D），[铺开] 进全空间自动排好；设置可改成打开就铺开 | 一打开就进全空间（会把别的应用藏起来，作为问题 1 交给用户定） |
| 3D 图表 | 文件里的标准图表按 3D 呈现；新建时写标准图表 | 自有的空间图表对象 |
| .html | 静态页面改文字写回；带脚本的整页只读；网页自己的空间化声明放 v1.x | 应用内做浏览器（不做） |
